# 작업 기록 — 사용한 스킬·도구와 검증 방법

2026-10-14 ~ 10-15 이틀 동안 Claude Code(Claude Opus 5.5)와 함께 만들었습니다. 방향과 화면 판단은 사람이 정하고, 구현과 검증은 Claude가 맡았습니다. 이 문서는 그 과정에서 **어떤 스킬과 도구를 언제 왜 썼는지**, **결과를 어떻게 확인했는지**, **확인하다 발견해 고친 문제**를 정리한 것입니다. 설계 결정 자체는 [PLAN.md](PLAN.md)에 있습니다.

## 1. 사용한 스킬

스킬은 Claude Code에 미리 정의해 둔 작업 절차입니다. 이번 작업에서 실제로 호출한 것은 세 가지입니다.

| 스킬 | 쓴 때 | 한 일 |
|---|---|---|
| `pickup` | 작업 시작 | 이전 세션 인계 문서를 읽고 목표·완료 항목·함정을 이어받음 |
| `decision-making` | 주제 선정 | "환율 대신 사내 위키 매뉴얼 챗봇으로 바꿀까"를 되돌리기 어려운 결정으로 보고 전제·맹점·트레이드오프를 따짐 → 위키 챗봇은 미션의 시계열·요약 요건과 맞지 않고 내부 문서 공개 위험이 있어 폐기, IT 트렌드 카드뉴스로 결정 |
| `frontend-design` | 프론트 구현 전 | 코드 전에 디자인 결정 6줄을 먼저 선언: Pretendard + IBM Plex Mono 2종, HN 오렌지 단일 주색 + 중립색, 4px 간격 단위, 경계선으로 면 구분, 라이트 기본 + 다크 모드, 로딩·빈 상태·오류·포커스 상태 구현 |

## 2. 사용한 도구

| 도구 | 용도 |
|---|---|
| Notion MCP | 미션 원문을 두 번 직접 읽어 요건과 대조. 두 번째 대조에서 README 필수 스크린샷(②데이터 관리, ③대화 불러오기)과 보너스 문서(도구 호출 근거·흐름) 누락을 발견 |
| context7 MCP | MCP Python SDK **v2.3.0** 공식 문서로 서버(`MCPServer`, `@mcp.tool()`)와 클라이언트(`list_tools`, `call_tool`) API를 확인한 뒤 작성. 기억에 의존한 API 사용을 피하기 위함 |
| Chrome DevTools MCP | 화면 검증의 중심. 로컬·배포 화면을 실제로 클릭해 DOM 결과와 소요 시간을 측정, 모바일(390×844) 에뮬레이션, README 스크린샷 촬영, Render 대시보드 수동 배포 |

| AskUserQuestion | 결과물이 달라지는 갈림길에서 확인. 예: 데이터 패널을 캘린더로 옮길지, 1위 글 제목을 따로 보존할지, 나머지 인기 글을 어떤 모양으로 보여 줄지, "6개씩 더 보기"가 전체 카드인지 제목 목록인지 |
| Claude Artifact | 화면 가이드 초안을 페이지로 공유 → 이후 앱 안에 내장한 투어로 대체 |

## 3. 단계별 진행과 검증

| 단계 | 내용 | 어떻게 확인했나 |
|---|---|---|
| M1 데이터 | HN 화제도 시계열 CRUD + 요약 + 130일 시드 | 5개 엔드포인트를 curl로 호출해 409(중복 날짜)·404·422(검증 실패) 응답 확인(PLAN 기록 기준). 요약·추세 계산은 `test_summary.py`(assert 기반)로 점검 |
| M2 채팅 | 요약 주입 채팅 + 대화 자동 저장 | 실제 GPT 응답에 요약 수치가 반영되는지, 이어 대화·불러오기 동작 확인. 확인용 대화는 확인 후 삭제 |
| M3 카드뉴스 | HN 인기 글 → 한국어 카드 → Firestore → 디스코드 | 디스코드 채널에 임베드 5장 게시 확인, 같은 날 다시 호출해도 중복 발송되지 않음 확인 |
| M4 프론트 | 요약·카드·채팅·데이터·대화 기록 | 로컬에서 CRUD·불러오기·채팅 클릭 확인, 390px 모바일 탭, 다크 모드 |
| M5 배포 | Render + Vercel + GitHub Actions(매일 08시) | 배포 URL 접속, Actions 수동 실행 1회 성공 |
| M6 문서 | README + 스크린샷 | 미션 원문과 항목 대조 |
| M7 보너스 | Function Calling 3종, MCP 서버, 그래프, CSV/JSON, 다크 모드 | 질문 유형별로 호출된 도구(`tools_used`)를 확인. MCP는 `mcp_server/check.py`로 stdio 연결 후 도구 목록·호출 확인 |
| M8 트렌드 캘린더 | memo를 "그날 트렌드 한 줄"로 바꾸고 캘린더 페이지 신설 | 트렌드 한 줄은 3~5일 샘플을 먼저 생성해 품질을 보고 프롬프트를 고친 뒤 131일 적재. 적재 후 빈 값·실패 대체값 0건 확인. 데스크톱·모바일 스크린샷으로 화면 확인 |
| M9 카드 속도·더 보기 | 날짜별 카드 미리 생성, 한 달 일괄 수신, 6개씩 더 보기 | 배포 화면에서 날짜 클릭부터 카드 표시까지 시간을 측정(아래 표). 로컬에서 "더 보기"를 두 번 눌러 번호 1~18 연속, 링크 중복 0건 확인 |
| 화면 가이드 | 메인·캘린더 첫 방문 투어 | 데스크톱·모바일에서 모든 단계를 자동으로 넘기며 스포트라이트 위치 오차(0px), 말풍선이 화면 안에 있는지, 대상을 가리지 않는지 측정 |
| README 보너스 문서 | 도구 호출 근거·흐름 | 예시를 지어내지 않고 배포 서버에 실제 질문 3개를 보내 호출된 도구를 기록한 뒤 작성. 확인용 대화는 삭제 |

## 4. 검증 원칙

- **눈으로 보지 않고 수치로 확인한다.** 화면은 Chrome DevTools로 실제 클릭한 뒤 카드 수, 소요 시간(ms), 요소 위치를 읽었습니다. 스크린샷은 사람이 볼 결과물을 확인하는 용도로만 썼습니다.
- **배포 후 배포본에서 다시 잰다.** 로컬에서 통과해도 배포 URL에서 같은 측정을 반복했습니다. Render는 공개 저장소 연결이라 자동 배포가 안 되므로, 배포 이벤트 로그에서 해당 커밋이 "Deploy live"인지까지 확인했습니다.
- **API 응답 모양이 바뀌면 백엔드를 먼저 띄운다.** 백엔드가 새 응답을 내는 것을 확인한 뒤 프론트를 배포해, 둘이 어긋나는 시간을 없앴습니다.
- **AI 출력은 샘플로 먼저 본다.** 전체 적재 전에 몇 건만 생성해 품질을 보고 프롬프트를 고쳤습니다.
- **로직에는 작은 자체 점검을 남긴다.** `backend/test_summary.py`(요약·추세), `services/blog_service`(RSS 날짜 파싱), `mcp_server/check.py`(MCP 연결), 정규식·필터는 assert로 경계값을 확인했습니다.
- **흔적을 남기지 않는다.** 확인용 대화는 확인 후 삭제하고 남은 대화 목록을 다시 조회했습니다(초기에 반복 호출로 8개가 쌓인 적이 있어 생긴 규칙). 커밋 전에는 비밀키·웹훅 주소가 섞이지 않았는지 검색했습니다.

## 5. 확인하다 발견해 고친 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 카드 요약이 "(없음)"으로 표시 | 원문 소개문이 없을 때 GPT가 입력의 "(없음)" 표시를 그대로 따라 씀 | 공용 번역 함수에서 걸러냄 → 오늘의 카드도 함께 해결. 저장된 카드 전수 검사 0건 |
| 트렌드 한 줄이 "AI와 소스 제어의 혁신적 변화"처럼 막연함 | 프롬프트에 형식·금지어가 없음 | "<가장 큰 소식>, <공통 흐름>" 형식, 고유명사 1개 이상, 추상어 금지 |
| 캘린더 칸 색이 거의 같아 진하기 차이가 안 보임 | 최댓값 대비 비율이라 27~56이 모두 비슷한 색 | 최저~최고 범위로 정규화 |
| 메인 화면이 비어 보임 | JS 문자열 안의 큰따옴표로 SyntaxError | 수정 후 모든 JS를 `node --check`로 문법 검사 |
| 모바일에서 숨긴 영역이 보임 | CSS 우선순위가 `[hidden]`을 덮어씀 | `:not([hidden])`로 한정 |
| 날짜를 처음 누르면 9.5초 | 131일 중 7일만 저장돼 있었음 | 전체 미리 생성 + 매일 발행 때 새 날짜도 생성 |
| 시연 대화의 숫자와 화면 요약이 다름 | 데이터를 다시 채우기 전에 받은 답 | 같은 질문으로 새로 받고 옛 대화 삭제 |
| 답변에 `**굵게**` 기호가 그대로 보임 | 프롬프트로 금지해도 GPT가 가끔 씀 | 저장 전에 서버에서 기호 제거(DB·MCP에도 깨끗하게 남음) |
| "인기 54개"인데 카드는 6장이라 헷갈림 | 숫자와 카드 수의 관계가 화면에 없음 | "인기 54" 표기, 카드 위 안내 문장, 6개씩 더 보기로 전부 볼 수 있게 함 |
| 백필 중 2일이 저장 안 됨 | GPT 응답 JSON이 깨짐 | 실패한 날은 저장하지 않게 해 두었으므로 빠진 날짜만 다시 실행 |

## 6. 남은 한계

- Render 무료 플랜은 15분 동안 요청이 없으면 잠들어, 첫 접속은 최대 50초 걸립니다. 화면에 안내 배너를 띄우고 자동 재시도합니다.
- HN 점수는 이틀 동안 오르므로 기록은 이틀 전 날짜까지만 확정합니다. 가장 최근 하루는 잠정값일 수 있습니다.
- 카드 13번째부터는 처음 볼 때 생성되므로 그 한 번은 10초 안팎 걸립니다.
